# TestFlight runbook

How to get a Crumb build into TestFlight, and the constraints that make it different from a
typical iOS app. Read the **iOS 27 constraint** section before promising anyone a build.

---

## 0. The iOS 27 constraint (read this first)

`CrumbKit` imports `FoundationModels` at the top level and uses the **dynamic-session API**
(`LanguageModelSession.Profile`, `.reasoningLevel(.deep)`) that ships only in the iOS 27
runtime. There are **no `@available` guards** on those call sites.

Consequences, all of them load-bearing:

| | |
|---|---|
| **Deployment target cannot be lowered.** | `options.deploymentTarget` in `project.yml` is `27.0` for iOS, macOS, and visionOS. A 26.0 build does not compile. |
| **Testers must run the iOS 27 beta.** | TestFlight will not offer the build to a device on iOS 26. iOS 27 GA is expected ~September 2026. |
| **The build machine needs Xcode 27.** | The default `xcode-select` may be 26.x. Prefix commands with `export DEVELOPER_DIR=/Applications/Xcode-beta.app/Contents/Developer`, or let `scripts/bootstrap.sh` do it. |
| **This Xcode beta is accepted for TestFlight.** | Apple enabled Xcode 27 beta 2 / iOS 27 beta 2 uploads for internal and external testing on June 23, 2026. Re-check the [App Store Connect release notes](https://developer.apple.com/help/app-store-connect/release-notes/) after changing Xcode betas. Uploading is not the problem; installing is. |

Fallback implementations exist (`RuleBasedCurator`, `RuleBasedRelevanceGate`, the on-device
tiers in `RecapWriter`). Wiring them behind `@available(iOS 27, *)` so a 26.0 build works is
**feature work, not configuration** — and it means the AI paths silently degrade on 26. That
tradeoff has not been taken. Do not lower the deployment target without doing that work.

## 1. Where build settings live

```
Config/Shared.xcconfig     signing, versioning              <- edit these
Config/Debug.xcconfig      #include Shared + debug flags     } exactly one of these
Config/Release.xcconfig    #include Shared + release flags   } applies per build
project.yml                targets, sources, schemes, deployment targets
Crumb.xcodeproj            GENERATED. gitignored. never hand-edit.
```

Debug and Release are selected per configuration — neither shadows the other. Each
`#include`s Shared, and a value redefined after the `#include` wins over Shared's.

**The `.xcodeproj` is a build artifact.** It is regenerated by `scripts/bootstrap.sh` and is
not tracked in git. Editing it by hand works right up until the next `xcodegen generate`
silently discards your change.

A subtlety worth internalizing: anything in `project.yml`'s `settings.base` is written
**inline** into the generated `pbxproj`, and inline settings **beat** the xcconfig. So a
setting must live in exactly one of the two. `bootstrap.sh` asserts that the xcconfig layer
actually got wired (`baseConfigurationReference` present) and that signing was not disabled,
because both failures are invisible until archive time.

## 2. One-time App Store Connect setup

1. **Accept the agreements.** developer.apple.com → Account → Agreements. The free-apps
   agreement must be accepted or builds cannot be distributed, even to internal testers.
2. **Register the App ID** `llc.crumb.Crumb` under Certificates, Identifiers & Profiles.
3. **Create the app record** in App Store Connect. Select **iOS, macOS, and visionOS**
   up front — adding a platform later is more painful than deselecting one.
4. **Add testers as App Store Connect users** (Users and Access), then as **Internal
   Testers** in the TestFlight tab.
5. **Create an internal group** and decide whether new builds should distribute automatically.
6. **Fill in Test Information:** beta description, feedback email, and concise "What to Test"
   notes. TestFlight builds remain available for 90 days.

## 3. Internal vs. external testing

**Start internal.** Up to 100 internal testers, no Beta App Review, builds available within
minutes of processing.

**Do not go external yet.** External testing (up to 10,000 testers) requires Beta App Review.
Crumb currently runs on `MockUCPClient` unless a `Secrets.plist` points it at a live broker,
and the curation/checkout paths are scaffolding. A shopping agent that cannot complete a
purchase is a likely **Guideline 2.1** rejection for incomplete functionality. Wait until the
UCP path is real.

## 4. Tested release workflow

Run releases from a clean, merged `main`. The script refuses to archive app changes that are not
committed. It also refuses to create a silent mock-catalog build when `Secrets.plist` is absent.

```bash
git fetch origin main
git switch main
git pull --ff-only origin main

cd projects/crumb-llc-app

# Contract checks for the release automation itself.
./scripts/tests/test_testflight.sh

# Full Crumb scheme on the iOS 27 simulator: app tests, CrumbKit tests,
# clean-install smoke test, accessibility checks, and end-to-end UI journeys.
./scripts/testflight.sh preflight

# Signed Release archive. BUILD_NUMBER must be unique for every upload.
BUILD_NUMBER="$(date -u +%Y%m%d%H%M)" ./scripts/testflight.sh archive

# Upload the existing archive with the internal-only export policy.
./scripts/testflight.sh upload
```

`submit` runs preflight, archive, and upload in one command:

```bash
BUILD_NUMBER="$(date -u +%Y%m%d%H%M)" ./scripts/testflight.sh submit
```

The default upload uses the developer account signed into Xcode. For CI, provide
`ASC_KEY_PATH`, `ASC_KEY_ID`, and `ASC_ISSUER_ID` together. The private key remains outside the
repository. `BUILD_NUMBER` defaults to a UTC timestamp when omitted, but setting it explicitly
makes archive provenance easier to record.

For an intentional mock-only build, set `ALLOW_MOCK_TESTFLIGHT=1`; never use that override by
accident. The normal path requires `Crumb/Resources/Secrets.plist` with an HTTPS
`CRUMB_API_BASE_URL`. The broker key is optional and rotatable.

After upload processing finishes, add the build to the internal group, enter "What to Test," and
verify one tester can install, launch, complete onboarding, run a mission, open the cart, and reach
the merchant handoff on an iOS 27 device.

## 5. Things that will bite you

**Missing Compliance.** `INFOPLIST_KEY_ITSAppUsesNonExemptEncryption: "NO"` is set on the
`Crumb` target in `project.yml`; `INFOPLIST_KEY_*` build settings are Xcode's supported way
to populate a generated Info.plist. Crumb uses only HTTPS, which is exempt from export
compliance. If a build nonetheless lands in *Missing Compliance*, answer the export
compliance question in the App Store Connect web UI — same outcome, one extra click.

**Slow processing.** Builds have been observed stuck in *Processing* for multiple days in
2026. Upload earlier than you think you need to.

**visionOS app icon.** `Assets.xcassets/AppIcon.solidimagestack` contains the layered
visionOS treatment generated alongside the iOS and macOS icons by `crumb-art-render`.
Keep the stack and renderer in sync when changing the icon; a flat iOS image is not a
substitute for the visionOS layers.

**Internal-only means internal-only.** `Config/ExportOptions-TestFlight.plist` sets
`testFlightInternalTestingOnly = true`. Apple marks those builds as internal; they cannot be added
to external groups or submitted to customers. Remove that restriction only in a separately
reviewed public-release change.

**Secrets.plist is expected to be absent from a fresh development clone.** It is gitignored, and
`UCPConfig.load(from:)` falls back to `.mock` when it is missing, so local development still works
with no setup. A normal TestFlight archive is different: `scripts/testflight.sh archive` requires
the local plist so internal testers exercise the live broker, unless an intentional mock build is
requested with `ALLOW_MOCK_TESTFLIGHT=1`.

**But do not put a real secret in it.** `Secrets.plist` is copied into the app bundle, so
anything in it ships inside the `.ipa` and is one `unzip` away from any tester. The current
design is deliberate and safe: no Shopify credentials on device (App Store rule 5.9 — the
broker holds them server-side), only the broker's base URL and an optional, rotatable,
broker-scoped `x-broker-key`. Keep it that way.

**Stale `.git/index.lock`.** If git refuses to write the index with *"Another git process
seems to be running"*, `rm -f .git/index.lock`.
